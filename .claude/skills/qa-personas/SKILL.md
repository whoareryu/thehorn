# 페르소나 QA 라운드

## 언제
구현 계획의 마일스톤(예: "사이트 골격", "목업 완성", "문서 서가")이 끝나 빌드와 검사가 초록일 때. `check_site.py` 가 빨가면 먼저 고친다 — QA 는 동작하는 것을 검사한다.

## 절차
1. `docs/qa/<YYYY-MM-DD>-<마일스톤>.md` 를 만들고 상단에 검사 대상 커밋 SHA 와 범위를 적는다.
2. Agent 도구로 다섯 페르소나(`qa-judge` `qa-voter` `qa-canon` `qa-teammate` `qa-frontend`)를 **한 응답에서 병렬로** 띄운다. 프롬프트에 마일스톤 범위와 "변경된 파일 목록"을 준다.
3. 다섯 보고를 합쳐 파일에 붙인다. 같은 발견은 하나로 합치고 심각도는 높은 쪽을 택한다.
4. P0 는 즉시 고친다. P1 은 이번 마일스톤 안에 고친다. P2 는 파일에 "보류 — 이유" 를 적는다. **발견을 조용히 넘기지 않는다.**
5. 고친 뒤 해당 페르소나만 다시 띄워 재검한다. 재검 결과를 같은 파일 하단에 "재검" 절로 붙인다.
6. 커밋 메시지에 `QA 라운드: docs/qa/<파일>` 을 인용한다.

## 페르소나가 보는 것
각 페르소나는 `.claude/agents/qa-*.md` 에 검사 항목이 있다. 여기 없는 것을 검사해 달라고 프롬프트에 덧붙일 수 있다.

| 페르소나 | 한 줄 |
|---|---|
| qa-judge | 과장 없이 자율성과 검증을 보여주는가 (Visual Guide §36, PART 1 §39) |
| qa-voter | 30초 안에 이해되는가, 용어·모바일·길 잃음 |
| qa-canon | 모든 문장·수치가 원문 v5.2 와 같은가, 제거된 설계가 남았는가 |
| qa-teammate | 이 사이트만 보고 P0 화면·에셋·Gate 를 오해 없이 아는가 |
| qa-frontend | 빌드·링크·반응형·접근성·단일 출처·검사 스크립트의 빈틈 |
