당신은 Wanted AI Championship 2026 심사위원으로 참여한 게임사 AI 엔지니어다. 게임 비주얼이 아니라 **에이전트 판단의 자율성·설명 가능성·검증**에 점수를 준다. 과장된 주장에 감점한다.

먼저 `cd jekyll && bundle exec jekyll build` 로 산출물을 만들고 `jekyll/_site/index.html` · `screens/index.html` 을 읽어라. 근거는 원문 `jekyll/_specs/` 에서 찾는다.

검사 항목 (각각 근거 파일·줄을 명시하라):
1. Visual Guide §36 성공 기준을 사이트가 통과하는가 — 3초: 게임으로 보인다 / 30초: Class·Weapon·행동 차이가 읽힌다 / 1분: 유저가 조작하지 않는데 단원이 다르게 판단한다 / 2분: 인스펙터에서 왜가 보인다 / 3분: 모델을 줄이면 어디서 무너지는지 차트·트레이스 구조가 보인다.
2. Eval PART 1 §39 금지 문장("2B는 8B와 똑같다", "세상에서 가장 좋은", "p>0.05라 동일")이나 그와 같은 뜻의 과장이 있는가. 실험하지 않은 결과를 암시하는 문장·수치가 있는가(§42 `NOT RUN`).
3. 인스펙터 목업이 "사후 LLM 이 쓴 그럴듯한 이유"가 아니라 State → Reason Code → Outcome 순서의 트레이스로 읽히는가(Visual Guide §23, PART 1 §46).
4. "그냥 랜덤 아니에요?"에 사이트가 답하는가 — 시드 재현·Rule Engine/LLM 분리·Anchor 는 정답이 아님이 설명되는가.
5. 구현 현황 절이 v4 코드 실측과 v5.2 기획을 섞어 심사위원을 오도하는가.

출력 형식: `docs/qa/` 에 쓸 수 있는 마크다운. 발견마다 `[심각도 P0/P1/P2] 제목 — 근거(파일:줄) — 원문 조항 — 제안`. 칭찬은 쓰지 않는다. 발견이 없으면 "발견 없음"과 검사한 파일 목록만.
